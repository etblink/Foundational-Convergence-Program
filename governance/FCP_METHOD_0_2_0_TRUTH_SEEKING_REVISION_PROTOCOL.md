# FCP Method 0.2.0 — Truth-Seeking Revision and Supersession Protocol

**Version:** 0.2.0  
**Status:** PROSPECTIVE CANDIDATE

## 0. Constitutional rules

```text
NO_RESULT_IS_IMMUNE_FROM_REVIEW = TRUE
HISTORICAL_RECORD_IS_IMMUTABLE = TRUE
CURRENT_CONCLUSION_MAY_BE_SUPERSEDED = TRUE
```

> **Preserve the historical record; supersede conclusions prospectively.**

## 1. Review triggers

### `APPLICATION_REAUDIT`

Trigger:
- credible evidence that an existing rule was applied inconsistently;
- arithmetic/transcription/classification error;
- framework-specific burden variation.

Burden:
show a concrete cross-case inconsistency under the same historical rule.

Output:
versioned reanalysis; historical artifact unchanged.

### `SOURCE_REAUDIT`

Trigger:
- material source omitted/misread;
- bound-source claim disputed;
- source packet too narrow for a load-bearing conclusion;
- public provenance failure.

Burden:
identify the source-level issue and plausible consequence.

Output:
source audit/strengthening candidate; no automatic score change.

### `METHOD_REVIEW`

Trigger:
- repeated application inconsistency traceable to ambiguous/defective rule;
- invariance failure;
- systematic over/under-credit;
- new case not representable without distortion.

Burden:
show framework-neutral defect and counterexample.

Output:
new method version; affected historical work listed for possible later reanalysis.

### `GOVERNANCE_REVIEW`

Trigger:
- review mechanism failed to activate despite material defects;
- methodological inertia or conflict of roles;
- unclear version authority;
- strategy systematically excludes higher-information work.

Output:
versioned governance change.

### `FRAMEWORK_TAXONOMY_REVIEW`

Trigger:
- umbrella framework contains materially different primitives/model classes/empirical burdens;
- framework split/merge materially affects comparison meaning.

Output:
prospective taxonomy decision; old IDs remain traceable.

### `RESULT_SUPERSESSION`

Trigger:
- qualified reanalysis or new source evidence changes the current best-supported conclusion.

Output:
new versioned current conclusion with:
- superseded artifact ID;
- reason;
- evidence;
- exact scope;
- unchanged historical object.

## 2. External adversarial criticism

External criticism enters as:

`EXTERNAL_HYPOTHESIS_GENERATING_ARTIFACT`

unless independently promoted by adjudication.

Required stages:
1. freeze artifact verbatim with provenance;
2. extract falsifiable/adjudicable claims;
3. independently check repository/source evidence;
4. classify each finding;
5. propagate only confirmed consequences.

Authority, popularity or rhetorical force never substitutes for adjudication.

## 3. Symmetric update rule

Review may:
- increase support;
- decrease support;
- narrow scope;
- broaden scope where justified;
- change zero to nonzero;
- change nonzero to zero;
- change resolved to unresolved;
- change unresolved to resolved.

No direction has default privilege.

## 4. Versioning

Historical files are append-only records.

Prospective correction uses:
- new versioned audit;
- new method/governance artifact;
- explicit compatibility/supersession map.

Do not silently edit old phase documents to reflect current understanding.

A live status/index file may later be updated only under separate authorization and must link both old and current conclusions.

## 5. Precommitment and outcome protection

Before applying a revised rule:
- freeze its text/hash;
- declare affected cases;
- declare expected failure modes;
- do not alter threshold after seeing which framework benefits.

If a rule changes after outcomes are viewed, version it again and rerun all affected cases symmetrically.

## 6. Anti-over-subtraction requirement

Every rejection/downgrade of a relation must include:
- `OVERCLAIM_TEST`;
- `OVER_SUBTRACTION_TEST`.

The reviewer must state both:
1. what stronger conclusion is unjustified;
2. what positive content remains after the downgrade.

## 7. Program strategy

FCP is one truth-seeking track, not the sole engine.

Prospective scheduling should balance:
- formal framework comparison;
- source strengthening where load-bearing;
- empirical/no-go work;
- provenance/reproducibility;
- genuinely distinct primitive-basis intake.

Program-level recurrence claims should not outrun method stabilization and source quality.

## 8. Stop/supersession discipline

A phase must stop at its authorization boundary.

A later dependency does not become authorized merely because the current phase recommends it.

## 9. Current prospective activation result

If Method 0.2.0 is later integrated, historical FCP-1–FCP-21 remain historical. No historical result is automatically rescored.

Targeted reanalysis requires separate authorization and an affected-case register.
