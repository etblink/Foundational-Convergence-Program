## 4. Pre-adjudication adversarial gate review

Before freezing this preregistration, the gate was attacked for outcome asymmetry, criterion overlap, hidden dynamical assumptions, over-admission, under-admission, realizability inflation, existing-framework absorption, and reporting distortion.

```text
PRE_ADJUDICATION_GATE_REVIEW = PASS_WITH_OPERATION_LEVEL_CLARIFICATIONS

```

### 4.1 Outcome asymmetry

New framework admission is deliberately harder than non-admission because admission asserts a stable foundational object. That asymmetry is acceptable only because:

- no scalar score is used;
- no recent negative FCP result receives precedent weight;
- a positive object that passes all burdens must be admitted;
- `PARTIAL` and `NOT_ESTABLISHED` are not silently converted to `FAIL`;
- lack of mature evidence may yield `UNRESOLVED` or `DEFERRED`, not automatic nonframework classification.

```text
ANTI_NEW_FRAMEWORK_DEFAULT = FORBIDDEN
PRO_NEW_FRAMEWORK_DEFAULT = FORBIDDEN
RECENT_FCP_REMOVAL_HISTORY_AS_PRIOR = FORBIDDEN
```

### 4.2 A, B, D, and F are not interchangeable

```text
A = WHAT_THE_OBJECT_PRIMITIVELY_COMMITS_TO
B = WHAT_STATE_PROCESS_CONFIGURATION_OR_MODEL_DOMAIN_IS_COHERENTLY_DEFINED
D = WHAT_PHYSICAL_SCOPE_AND_MODEL_CLASS_THE_OBJECT_CLAIMS
F = WHETHER_CROSS_SOURCE_CONTINUITY_IS_SUFFICIENT_TO_IDENTIFY_THE_OBJECT_STABLY
```

`F` is partly an evidentiary-maturity burden. Therefore:

```text
F_NOT_ESTABLISHED_ALONE != SUBSTANTIVE_NONFRAMEWORK_PROOF
F_PARTIAL_ALONE != SUBSTANTIVE_NONFRAMEWORK_PROOF
```

If all substantive burdens are otherwise live but cross-source continuity is insufficient, the controlling disposition must be `UNRESOLVED` or `DEFERRED` rather than a fabricated substantive rejection.

An affirmative `F = FAIL` may support nonframework or fragmentation only when the corpus positively establishes incompatible or merely aggregative object identities rather than merely lacking enough literature.

### 4.3 Criterion C interpretation

Criterion C remains:

```text
C = INTRINSIC_DYNAMICS_OR_SOURCE_BOUND_FRAMEWORK_LEVEL_DYNAMICAL_ARCHITECTURE
```

It does not require a preferred external time coordinate, Hamiltonian trajectory language, or one specific mathematical representation of dynamics.

It **does** require more than:

```text
BARE_COMPOSITION
BARE_ADMISSIBILITY
A_SET_OF_ALLOWED_MAPS_WITHOUT_PHYSICAL_LAW_CONTENT
FORMAL_CLOSURE
RESOURCE_LABELING
IMPLEMENTATION_CONTROL_STRUCTURE
```

A source-bound constraint/process/history architecture may satisfy C only if it functions as physical framework-level law content governing admissible evolution, processes, histories, or physical transformations—not merely as mathematical syntax or a catalog of possible operations.

This clarification is not a process-matrix-specific relaxation.

### 4.4 E and H do not double-count

```text
E = SOURCE_BOUND_MEASUREMENT_REALIZATION_OR_PHYSICAL_INTERPRETATION_BURDEN
H = EXPLICIT_EMPIRICAL_OR_OBSERVATIONAL_BURDEN
```

E asks whether the object has a physically interpretable bridge from formalism to systems/measurements/realizations. H asks what empirical consequences, exclusions, compatibility obligations, or observational burdens the object bears.

No scalar aggregation is used, so evidence cannot receive extra credit merely by appearing under both fields.

### 4.5 G does not make distinctness sufficient

```text
G = PRINCIPLED_DISTINCTION_FROM_EXISTING_FCP_FRAMEWORKS_AND_GENERIC_REPRESENTATIONAL_OR_METHOD_TOOLING
```

`G = PASS` means only that an object is not adequately reduced to an existing framework or generic formalism. It does not establish foundationality. A–F and H remain independently required.

Likewise:

```text
DISTINCTNESS != ADMISSION
NONIDENTITY_WITH_CQM != NEW_FRAMEWORK
NONIDENTITY_WITH_GPTOPT != NEW_FRAMEWORK
```

### 4.6 Existing-framework absorption control

Existing-framework mapping requires positive identity coverage, not mere overlap.

For any proposed mapping to `FW-CQM`, `FW-GPTOPT`, or another existing FCP framework, record separately:

```text
REPRESENTATIONAL_OR_OPERATIONAL_OVERLAP
PRIMITIVE_IDENTITY_COVERAGE
MODEL_DOMAIN_IDENTITY_COVERAGE
LAW_OR_DYNAMICAL_ARCHITECTURE_COVERAGE
PHYSICAL_SCOPE_COVERAGE
EMPIRICAL_BURDEN_COVERAGE
RESIDUAL_CONTENT_NOT_COVERED
```

A mapping is permitted only if the existing framework is the weakest adequate classification of the source-bound object. Shared language, embeddings, implementations, or special cases are insufficient.

```text
OVERLAP != IDENTITY
SPECIAL_CASE_IMPLEMENTATION != OBJECT_IDENTITY
EXISTING_FRAMEWORK_AS_DUMPING_GROUND = FORBIDDEN
```

### 4.7 Mathematical-unity control

```text
SHARED_LINEAR_ALGEBRA != PHYSICAL_UNITY
SHARED_CATEGORY_THEORY != PHYSICAL_UNITY
SHARED_COMPOSITIONALITY != PHYSICAL_UNITY
SHARED_HIGHER_ORDER_MAP_LANGUAGE != PHYSICAL_UNITY
SHARED_CAUSAL_TERMINOLOGY != PHYSICAL_UNITY
```

Mathematical or representational unity can support a formalism classification but cannot by itself merge scientific objects or satisfy A, C, E, G, or H.

### 4.8 Model-family coherence control

A coherent model or process family does not automatically pass framework admission.

```text
STABLE_MODEL_CLASS != FOUNDATIONAL_FRAMEWORK
RESOURCE_THEORY != AUTOMATIC_FOUNDATIONAL_FRAMEWORK
PROPERTY_CLASS != FOUNDATIONAL_FRAMEWORK
IMPLEMENTATION_FAMILY != FOUNDATIONAL_FRAMEWORK
```

The taxonomy may preserve such objects positively without promoting them.

### 4.9 Empirical back-projection control

```text

CAUSAL_INEQUALITY_RESULT != UNIVERSAL_ICO_FRAMEWORK_RESULT

```

### 4.10 Realizability stratification

Realizability is not binary. For every load-bearing realizability proposition, classify the claim at the weakest adequate layer:

```text
R0 = FORMAL_PROCESS_VALIDITY
R1 = STANDARD_QUANTUM_MODEL_REALIZATION
R2 = SUBSYSTEM_OR_FACTORIZATION_DEPENDENT_REALIZATION
R3 = TIME_DELOCALIZED_SUBSYSTEM_REALIZATION
R4 = CLOSED_LOCAL_LABORATORY_REALIZATION
R5 = CLASSICAL_SPACETIME_EMBEDDED_REALIZATION
R6 = CONCRETE_EXPERIMENTAL_IMPLEMENTATION
```

These are descriptive layers, not a monotone ladder of universal implication. A result at one layer may depend on assumptions that make another layer inapplicable.

Each realizability record must state:

```text
REALIZABLE_OBJECT
PHYSICAL_ASSUMPTIONS
LABORATORY_BOUNDARY_ASSUMPTIONS
SUBSYSTEM_FACTORIZATION
IMPLEMENTATION_SCOPE
NEGATIVE_RESULT_DOMAIN
UNAUTHORIZED_GENERALIZATION
```

A negative result at one layer cannot be generalized to all process matrices, all ICO, or all physical realizability unless the frozen source explicitly has that scope.

Historical taxonomy gates sometimes emitted one top-level A/B/C/D/E verdict. This operation does not require a single letter because a heterogeneous corpus may contain multiple scientifically valid object types simultaneously.

This is an operation-level reporting revision, not a change to framework-admission burdens.


## 7. Ordered A–H framework-admission test

Only objects whose weakest adequate classification may be a foundational physical framework proceed to A–H admission.

```text
A = SOURCE_BOUND_PRIMITIVE_COMMITMENTS_OR_PHYSICAL_OBJECT_CLASS
B = COHERENT_STATE_PROCESS_CONFIGURATION_OR_MODEL_DOMAIN
C = INTRINSIC_DYNAMICS_OR_SOURCE_BOUND_FRAMEWORK_LEVEL_DYNAMICAL_ARCHITECTURE
D = STABLE_PHYSICAL_SCOPE_AND_DECLARED_MODEL_CLASS
E = SOURCE_BOUND_MEASUREMENT_REALIZATION_OR_PHYSICAL_INTERPRETATION_BURDEN
F = CROSS_SOURCE_CONTINUITY_SUFFICIENT_FOR_OBJECT_SPECIFIC_K1_K10
G = PRINCIPLED_DISTINCTION_FROM_EXISTING_FCP_FRAMEWORKS_AND_GENERIC_MATHEMATICAL_REPRESENTATIONAL_OR_METHOD_TOOLING
H = EXPLICIT_EMPIRICAL_OR_OBSERVATIONAL_BURDEN
```

Each field is one of:

```text
PASS
PARTIAL
FAIL
NOT_ESTABLISHED
```

Final framework admission is:

```text
PASS
FAIL
UNRESOLVED
```

Decision discipline:

```text
ADMISSION_PASS = ALL_A_H_PASS

ADMISSION_FAIL =
AT_LEAST_ONE_SUBSTANTIVE_A_H_FIELD_AFFIRMATIVELY_FAILS
AND_THE_FAILURE_IS_NOT_MERELY_EVIDENCE_IMMATURITY

ADMISSION_UNRESOLVED =
NO_CONTROLLING_SUBSTANTIVE_FAIL
AND_AT_LEAST_ONE_REQUIRED_FIELD_IS_PARTIAL_OR_NOT_ESTABLISHED
```

A `FAIL` must state what positive scientific content survives after rejection. A `PASS` must state why the object is not merely a model/process/resource/implementation family. An `UNRESOLVED` disposition must state the exact missing proposition and may not receive a provisional `FW-*` identifier.
