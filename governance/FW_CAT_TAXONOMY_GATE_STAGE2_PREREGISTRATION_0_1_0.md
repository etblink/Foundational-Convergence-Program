## 6. Ordered framework-admission test

Only after object separation, each resulting object will face:

```text
FRAMEWORK_ADMISSION_TEST =
IS_THE_SOURCE_BOUND_OBJECT_A_FOUNDATIONAL_PHYSICAL_FRAMEWORK_RATHER_THAN_A_MATHEMATICAL_LANGUAGE_REPRESENTATION_TOOL_RECONSTRUCTION_SCHEME_MODEL_FAMILY_OR_EXISTING_FRAMEWORK_REFORMULATION

FRAMEWORK_SEPARATION_TEST != FRAMEWORK_ADMISSION_TEST
```

For every candidate object, adjudicate without scalar aggregation:

```text
A = SOURCE_BOUND_PRIMITIVE_COMMITMENTS_OR_PHYSICAL_OBJECT_CLASS
B = COHERENT_STATE_PROCESS_CONFIGURATION_OR_MODEL_DOMAIN
C = INTRINSIC_DYNAMICS_OR_SOURCE_BOUND_FRAMEWORK_LEVEL_DYNAMICAL_ARCHITECTURE
D = STABLE_PHYSICAL_SCOPE_AND_DECLARED_MODEL_CLASS
E = SOURCE_BOUND_MEASUREMENT_REALIZATION_OR_PHYSICAL_INTERPRETATION_BURDEN
F = CROSS_SOURCE_CONTINUITY_SUFFICIENT_FOR_OBJECT_SPECIFIC_K1_K10
G = PRINCIPLED_DISTINCTION_FROM_EXISTING_FCP_FRAMEWORKS_AND_GENERIC_MATHEMATICAL_REPRESENTATIONAL_OR_METHOD_TOOLING
H = EXPLICIT_EMPIRICAL_OR_OBSERVATIONAL_BURDEN
```

Each A–H field will be `PASS`, `PARTIAL`, `FAIL`, or `NOT_ESTABLISHED`; the final object-level admission will be `PASS`, `FAIL`, or `UNRESOLVED`. Empirical success is not required, but exemption from a meaningful empirical burden is not permitted.
