## 2. Invariance tests

### 2.1 Framework-label invariance

Replace framework names with A/B/C while preserving evidence records.

Result:
same E2/E3, lineage, target-conditioning, viability and empirical rules apply.

`FRAMEWORK_LABEL_INVARIANCE = PASS`

### 2.2 Target-role invariance

Controlled recovery uses the same E3 requirements regardless of framework identity. Direction remains explicit: source→target is not symmetric merely because the burden is symmetric.

`TARGET_ROLE_INVARIANCE = PASS`

### 2.3 Packet-format invariance

An already-bound source can qualify a relation whether or not every theorem detail was recopied into the current packet.

Scientific classification depends on source support, not packet verbosity.

`PACKET_FORMAT_INVARIANCE = PASS`

### 2.4 Lineage invariance

AQFT/QFT, CQM/QM, LOOP/GR and AS/GR all use the same independence questions:
- shared ancestry;
- direct import;
- target conditioning;
- shared empirical input;
- later cross-fertilization.

`LINEAGE_INVARIANCE = PASS`

### 2.5 Calibration invariance

Missing detector calibration:
- does not erase mathematical E1–E3;
- caps physical/empirical promotion identically.

`CALIBRATION_INVARIANCE = PASS`

### 2.6 Target-conditioning invariance

Target-conditioned recovery:
- can be `V2/V3` viability evidence;
- is not independent rediscovery of the target;
- does not inherit empirical credit automatically.

Applied identically to CST/LOOP/AS and any future framework.

`TARGET_CONDITIONING_INVARIANCE = PASS`

### 2.7 Null-role invariance

Declaring `CR-EI`, `CR-RT`, `CR-FC`, `CR-CB` prevents the null object from silently changing evidentiary burden.

`NULL_ROLE_INVARIANCE = PASS`

### 2.8 Outcome invariance

Method 0.2.0 thresholds are defined before any future framework application and are justified by cross-case defects already adjudicated.

`OUTCOME_INVARIANCE = PASS`
