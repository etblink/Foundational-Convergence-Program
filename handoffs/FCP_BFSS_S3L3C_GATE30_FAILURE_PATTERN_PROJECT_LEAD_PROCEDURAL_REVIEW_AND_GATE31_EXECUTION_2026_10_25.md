**E. Honest record keeping.** Repeated independent green runs of the same theorem are not new mathematical roots. An accepted theorem in a cache is not an accepted next theorem; a compiler error from the strict warning linter still makes the gate red; an error at a preceding module is not evidence against a later untouched statement. ## 3. What repeatedly failed us, and the underlying correction

| Recurrent anti-pattern | Why it fails | New operating rule |
| --- | --- | --- |
| Guessing broad simp calls in reversed equalities | `h : i=j` and `h.symm : j=i` can cause loops, unnecessary rewrites or fail to simplify the opposite condition | Give each branch an explicit typed equality/inequality fact; use only the facts for that branch; check exact elaborated goal |
| Cosmetic one-token linter edits without checking logical goals | Gate30 #2→#3 merely moved an unused lemma while revealing `j=i → ...` as an undischarged obligation | Diagnose *all* compiler errors on the affected proof and prove the residual proposition explicitly |
| Fragile generated `split_ifs` hypothesis names | Simplifier can discharge/prune branches; generated binder names may be missing/unused | Use stable `by_cases`-scoped hypothesis and separately typed auxiliary equalities when helpful |
| Deprecated Lean APIs and blanket warning suppression | `if_pos/if_neg`, `ContinuousLinearMap.add_apply` are disallowed in the actual strict toolchain | Use current stable simp forms in EXACT proof-only adapters; no disabling `warningAsError`, linter or axiom scanner |
