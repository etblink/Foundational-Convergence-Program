# FCP handoffs — navigation and document hygiene

This directory contains distinct document types. **Do not treat a historical handoff as live project status.**

## Start here: permanent Project Lead guidance

**[FCP Project Lead — Evergreen Research Guidance](./FCP_PROJECT_LEAD_EVERGREEN_RESEARCH_GUIDANCE_0_1_0.md)**

This is the canonical module-independent guide for truth-first research decisions, formal verification, failure classification, negative-knowledge stewardship, and honest scientific boundaries. Update it **only for durable methodological changes**, not individual runs.

## For active work

Use the latest scoped successor handoff and verify the named research branch, PR state, source pins, open hypotheses, and exact CI evidence. Do not assume any old "latest green" entry remains current.

## For research history and negative knowledge

Module- and experiment-specific reports belong in scoped handoffs or `handoffs/archive/`. Examples:

- [BFSS S3L cubic experiment history snapshot](./archive/BFSS_SU2_S3L_CUBIC_VERIFICATION_AND_GATE_HISTORY_SNAPSHOT_0_1_0.md) — historical preserved content from the former methodology file; **not** evergreen.
- [BFSS S3L K2C failed-gate diagnostic record](./BFSS_SU2_S3L_K2C_GATES_1_TO_10_NEGATIVE_KNOWLEDGE_AND_RESEARCH_REDIRECT_0_1_0.md) — narrowly scoped evidence, not universal policy.
- [BFSS S3L project succession record](./BFSS_SU2_S3L_PROJECT_LEAD_PROOF_ENGINEERING_AND_TRUTH_BOUNDARY_HANDOFF_0_1_0.md) — dated state and experimental lessons requiring live verification.

**Maintenance rule:** Route each new fact by *kind*, not by how important it feels. Gate numbers and commits → scoped record. Current next steps → live handoff. Lasting cross-project method → evergreen guide. Never copy a whole running diary into the evergreen file.
